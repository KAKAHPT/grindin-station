# M10 — Export tournament data for official reporting (2026-11-05)

Owner's ask (2026-11-04): stores must report results to Wizards (EventLink) or risk penalties; without an
export they have little reason to use Grindin. Research (`docs/superpowers/notes/2026-11-05-m10-export-research.md`,
checked 2026-11-04): EventLink imports **only a player invite list** (CSV, Wizards account e-mail or display name
in column A), has no results import or public API, identifies players by Wizards account e-mail / Companion /
guest name, and files Commander events as "Player List Only" (no rounds). Melee imports players
(`Email, FirstName, LastName, WizardsAccountDisplayName`). TopDeck imports pairings (`Table, Player1..N`) and
exports standings with `standing, name, id, points, winRate, opponentWinRate, wins, draws, byes`.

So the export must (a) feed EventLink's invite list and Melee's player import directly, (b) make manual entry
fast with a printable results sheet, and (c) give standings/rounds/pairings CSVs for records, TopDeck and
spreadsheets.

Global constraint (owner, 2026-11-04 night): the M7 design everywhere; the Export card uses `card` +
`card-title`, `ctable`, `button_classes(:secondary, size: :sm)`; the sheet uses the `print` layout. Layouts
reviewed with the owner the next morning.

## 1. Wizards account e-mail

- `players.wizards_email` string, nullable. Edited at `/account` ("Wizards account e-mail", hint "Used by
  organizers to report your results to Wizards EventLink. Leave empty to use your sign-in e-mail."). Shown to
  staff only (roster desk, exports); never public; `Accounts::Anonymize` clears it.
- `Player#reporting_email` = `wizards_email.presence || user&.email_address`.

## 2. Files (all `GET`, organizer namespace, roles `organizer` + `scorekeeper`)

Routes under `/organizer/tournaments/:id/export/` (and the same under leagues where it makes sense: players,
standings, rounds):

| Path | Format | Columns / content |
|---|---|---|
| `players.csv` | EventLink invite list | one column, no header: `reporting_email`, or the player's name when there is no e-mail (guest) |
| `melee.csv` | Melee player import | header `Email,FirstName,LastName,WizardsAccountDisplayName`; first name = first word of the name, last name = the rest (or the first word again when single); display name = handle |
| `standings.csv` | records / spreadsheets | header `standing,name,email,points,wins,draws,losses,byes,winRate,opponentWinRate` (multiplayer) or `standing,name,email,points,wins,draws,losses,byes,omw,gw,ogw` (1v1); rates as `0.000` (blank when the player has no games yet, like the feed); order = `Feeds::Standings.ranked`; dropped players included after the active ones with `dropped` as a final column `yes/no` |
| `rounds.csv` | long format, all rounds | header `round,table,seat,player,email,result,gamesWon,gamesLost,gamesDrawn`; `result` in `win,draw,loss,bye,eliminated,advance,penalty`; cut rounds use the round's cut name in `round` |
| `pairings.csv?round=N` | TopDeck pairings import | header `Table,Player1,Player2,Player3,Player4,Player5`; one row per table; defaults to the latest published round |

CSV: UTF-8 with BOM, `\r\n`, `Content-Disposition: attachment; filename="<slug>-<kind>.csv"`. Built by POROs
`Exports::Players`, `Exports::Melee`, `Exports::Standings`, `Exports::Rounds`, `Exports::Pairings`, each
`self.call(event, **opts) -> String`, in `app/services/exports/`. Names use the roster display name (same as
standings). Every download writes an audit event `data_exported` (`kind`) via `Audit.record` (M9).

## 3. Results sheet (`export/sheet`, `print` layout, A4)

For manual EventLink entry: page 1 the player list (name, reporting e-mail, dropped); then one block per
round: table number, players with seat, result (W/D/L, 1v1 with games), byes listed; last page the final
standings (standing, name, points, record). Header on each page: event name, date, organizer, "Generated
<time>". Works for finished and ongoing events (only closed rounds).

## 4. Organizer page

Overview tab gets an **Export** card (after the structure card): a `ctable` with one row per file: name, one
line of purpose ("EventLink invite list", "Melee player import", "TopDeck pairings import", "Final standings",
"All rounds, one row per seat", "Results sheet for manual entry"), and a `button_classes(:secondary, size: :sm)`
"Download" / "Open" link. Under it a two-line note: "EventLink has no results import. Commander events are
filed as Player List Only: upload `players.csv` as the invite list and end the event." (en/pt/es).
Pairings link appears only when a round is published; sheet/standings/rounds whenever the event has a round.

## 5. Tests

- `Player#reporting_email`; account form saves `wizards_email`; anonymize clears it; it is not on any public
  page (profile test).
- Each `Exports::*` service with a `TournamentBuilder` event after two played rounds (multiplayer) and one 1v1
  event: exact header, row count, a spot-checked row, BOM, CRLF; pairings default round and `?round=`.
- Controller: organizer and scorekeeper get 200 with the attachment headers; judge and non-staff are refused;
  audit row written; sheet renders with the `print` layout and contains each round.
- Overview card shows the rows and hides pairings before a published round.

## Out of scope

Pushing to EventLink/Melee/TopDeck (no APIs), DCI numbers, PDF generation (the sheet is printed from the
browser like the pairings), e-mailing exports.
